# 角色表达修复计划审核三｜可部署性与真实验收｜v0.01

审核对象：第二轮修订后的 `DeploymentPlan部署方案-v0.12.md`

## 独立审核范围

只审核测试能否证明行为已修复，以及最终通知是否真的来自贾南风。

## 结论

`PASS（修订后）`

## 发现与修订

- 文件存在不能代替行为验收。已要求八个 Agent 分别用新隔离 session 实际回复。
- “符合角色”过于主观。已补为：现有角色锚点、首句直接回答、工程字段禁用、状态事实和零虚构五项判据。
- 普通回复通过不能证明技术问答。已补 housekeeper、ops、reviewer 的“明确索要技术细账”测试。
- 模型额度失败不能循环。已补为：显式指定已核实可用模型，单次失败即停止该模型，不自动反复尝试。
- 人工用 Bot API 发送预写文本不能证明角色卡。已补为：最终完成通知必须由 housekeeper Agent 在真实 Telegram 路由中生成并发送，并核对 transcript 与 message ID。

部署后的完成门按本审核真实执行：首次最终成稿仍带系统组件清单，因此被判失败；补强规则并完成八角色对抗测试后，第二次真实 Agent 通知才获通过。

三轮审核结束后，正式计划才进入生产部署。
