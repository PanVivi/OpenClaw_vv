# OpenClaw 最终设计｜v1.11｜晨报与确定性工作流增量

本文件完整继承 v1.10，以下内容为新的权威增量。

## 1. 晨间玉简

输出合同固定为 2026-08-04 11:54 版本：宗门抬头、少主亲启、公历农历、晨辞、七个完整框、定稿分隔线和结尾祝辞缺一不可。数据不足时保留区块并自然说明，不以 `[待确认]` 或模拟数字填充。

晨报程序、运行状态和 owner 输入各自持久化；06:00 command Cron 是唯一触发。life 的专用 Tool 负责 schema、日期、原子写入、回读、提醒和投影；角色文件只负责理解与表达。

## 2. 输入与转交

life 可维护抬头/祝语、地点和天气关注、空气敏感、衣行偏好、生活待办、门人备注、日程和小签偏好。天气、AQI、农历、门人在线和系统任务事实只读。

housekeeper 收到同类信息时建立持久 handoff，life 按 handoff ID 应用。`pending/applying/blocked` 都不是完成，只有写入成功后的 `applied` 回执才算录入。事件时刻与提醒时刻分离，非默认事件默认提前 60 分钟。

## 3. 工作流与风险

正式多步任务采用四层：Standing Orders 说明角色和边界；Skill 提供完整操作手册；Plugin 执行计划哈希、三次独立完整审查、阶段、子任务、验收和通知硬门；官方 Task Flow 保存唯一运行事实。

风险策略为：低风险自动；中风险内部完整复核、备份和回滚就绪后自动；高风险在副作用前由角色自然说明并只询问一次。通用高风险 exec 被 fail-closed 拦截，不调用原生审批卡；没有专用受控能力时保持 blocked。

## 4. 当前版本限制

OpenClaw 2026.7.1-2 没有 Task/Flow mutation Hook，旧 Workboard 派发和通知尚不能完全事件化。两个分钟轮询只有在替代链真实验收后才能停用。Telegram ambiguous 进入人工核对，禁止自动重发。
