# 角色表达修复计划审核｜v0.01

审核对象：`DeploymentPlan部署方案-v0.12.md`

## 第一轮：官方机制一致性

审核范围只包括 OpenClaw 的 bootstrap、角色文件职责、子 Agent 上下文和消息发送机制。

### 发现

1. **根因层级正确**：计划区分了模型生成回复与不经过模型的 Relay 固定模板。只改角色卡无法改变 Relay，判断成立。
2. **文件选择正确**：人格与语气进入 `SOUL.md`，可执行输出规范进入 `AGENTS.md`，身份继续沿用 `IDENTITY.md`；未采用官方固定 bootstrap 之外的新 `STYLE.md`。
3. **全局 Hook 被正确排除**：官方 Hook 能重写消息，但对八个角色所有自由文本做统一确定性改写会扩大故障面，并可能损坏事实，不适合本轮。
4. **需要补强**：官方 system prompt 说明子 Agent 只取得精简 bootstrap。计划虽同时修改 `SOUL.md` 与 `AGENTS.md`，但原稿未明确 `AGENTS.md` 必须自足，也未把八个 workspace 的真实 bootstrap 路径列为验收项。

### 修订

已在正式计划中补入：

- `AGENTS.md` 的用户表达规则必须独立可执行，不得只引用 `SOUL.md`。
- 部署前固定八个真实 workspace/bootstrap 报告。
- 验收时检查八个新 session 分别加载自己的 workspace，且关键规则未截断。

### 结论

`PASS（修订后）`

计划与 OpenClaw 官方机制一致，可以进入第二轮无损与安全审核。

## 第二轮：无损、安全与并发

审核范围只包括线上切换、消息重复、游标、凭据、会话记忆和回滚。

### 发现

1. **无损边界正确**：计划没有修改 `openclaw.json`、agent ID、binding、A2A、模型、权限、会话或记忆。
2. **备份边界需要明确**：线上备份可能包含配置或凭据，必须只留在 NAS，不进入 Git。
3. **并发切换需要补强**：Relay 每分钟运行；若在脚本替换中刚好触发，可能发生新旧模板交叉。应短暂停止 Relay Cron，但不能停止 Workboard 调度泵，也不能删除事件。
4. **重复发送风险需要明确**：回滚时不得回退 cursor，否则会把历史事件重新发给少主。
5. **不可信文本需要收口**：任务标题来自工作流，不应允许换行、控制字符、UUID 或超长标题破坏通知结构。

### 修订

已在正式计划中补入：

- 备份仅保留在 NAS。
- 切换时只暂停 Relay Cron；Workboard 事件继续持久化。
- 自测通过后恢复 Cron并核对 cursor。
- 回滚不得回退 cursor 或清除 audit。
- Relay 对标题做控制字符、UUID、时间戳、测试标签和长度清理。

### 结论

`PASS（修订后）`

计划不会破坏聊天记忆和既有工作流，且已有可控切换与回滚路径，可以进入第三轮可部署与真实验收审核。

## 第三轮：可部署性与真实验收

审核范围只包括测试是否能证明修复有效，以及完成通知是否真的来自贾南风。

### 发现

1. **不能以文件存在代替行为验收**：原计划已要求八个 Agent 使用新 session 实测，方向正确。
2. **角色判据需要可执行**：仅写“符合语气”主观性过高，至少应检查现有角色锚点、首句直接回答、工程字段禁用和状态事实。
3. **技术模式也要验收**：若只测试普通回复，可能导致角色在少主索要细账时再次退化为无角色的工程模板。需要对最相关的 housekeeper、ops、reviewer增加技术细账测试。
4. **模型重试需要封顶**：此前已经出现额度不足模型被反复调用的问题。本轮应显式使用已核实可用模型，明确失败即停止该模型，不允许无意义循环。
5. **最终通知必须是真 Agent 行为**：只用 housekeeper Bot account 发送人工预写文本不能证明贾南风角色卡生效。最终通知应由 housekeeper Agent 通过真实 Telegram 路由生成，并核对 transcript 与 message ID。

### 修订

已在正式计划中补入：

- 八角色可执行验收判据。
- housekeeper、ops、reviewer 的技术细账追加测试。
- 显式可用模型与禁止额度失败循环。
- 最终 Telegram 通知必须由 housekeeper Agent 生成并发送，不能用人工预写 Bot 文本冒充。

### 结论

`PASS（修订后）`

三轮审核均已完成。修订后的计划与官方机制一致、可无损回滚、能够用真实行为证明结果，可以按计划开始部署。
